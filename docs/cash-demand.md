# 有日期的现金需求压力情景（待审）

复用现有 account-exposure-input-v1 的共同币种、基础金额、估值日、根持仓及可用/冻结现金。本批独立情景不会把基金底层证券或基金间接现金再计入账户现金，也不改变工作台的账户/基准接口、收益率账本或既有冻结输出。

## 调用与留档

```sh
python -m portfolio_engine cash-demand --input examples/cash-demand-demo.json --out reports/cash-demand
python -m portfolio_engine verify reports/cash-demand
```

打开 cash-demand-report.html；输出 cash-demand.json、各情景 cash-ledger-N.csv、source-input.json 和 report-manifest.json。目录必须不存在，修改输入或参数后另选新目录，旧结果不覆盖。输入版本 cash-demand-input-v1、结果 cash-demand-result-v1、方法 conditional-dated-cash-demand-v1；requested_method_version 可明确绑定方法，不支持的版本拒绝。

公开发行仍是 v0.7.0，本功能待审。原 #1 → #2 → #3 → #4 → #5 → #6 依赖顺序保留，本批接在 #6 后，不合并、不发新版。原创 MIT，第三方及数据权利范围不变。本教学输入不含真实账户、原文全文或 Wind 数据。

## 需要哪些显式输入

- account：已有账户敞口契约，全部根资产同币种/同估值日，以该日收盘声明作为起点。现金总额包括冻结部分，可用=总现金-冻结；基金间接现金不加入可用现金。
- cashflows：独立外部 income 或 necessary_expense、金额、日期及来源假设；经济事件标识必须唯一。金额或日期为 null 时保留未知，而非0。同估值日事件拒绝，防止把已经包含在收盘现金的事项再次记入；日期在起点之后且不晚于期限。
- frozen_releases：现金根持仓、解冻金额/日期、条件描述、condition_met（true/false/null）和来源。总计划金额不能超过原冻结现金；只在条件明确为真且日期已知时转为可用。关闭解冻或条件为假时保留冻结；日期/条件未知时列未知。迟于期限不提前入账。
- liquidity：只能对应非现金根资产，不是穿透叶子。can_sell、基础折价、费用比例、最早可卖日、到账天数及依据独立声明；日基准须明确 calendar，本版不推断交易日/节假日日历。费用只支持 deduct_from_settlement_proceeds。缺任何所需依据均不默认可卖、零费或及时到账。
- planned_liquidations：明确预定的根持仓、账面变现额及日期，不自动选资产；同资产累计预定金额不能超过起点账面金额。每个事件的 id/economic_event_id 跨收入、解冻、变现列表唯一，不能把同一笔回款再作为外部收入导入。
- scenarios：正常、收入中断、追加折价、到账延迟或禁用解冻等用户压力参数。收入保留比例仅支持0到1，削减必须给 income_change_from；追加折价0到1，总折价=min(1,基础+追加)，延迟以声明的日历天计算。未知或不支持的压力字段拒绝，不推断概率。

## 三类金额不能混用

**账面市值**是起点根资产金额。**条件净可变现估值**=账面金额×(1-总折价)×(1-费用率)，只说明声明条件下的估值，不等于可用现金。**可用现金**仅在收入、解冻或预定变现净额按明确日期到达后变化。费用已从到账净额扣除，不能再作为同一事件的支出重复扣。

每日条件余额=期初可用+收入+明确解冻+预定净到账-必要支出。解冻只是现金状态变化，不产生新的账户财富。相同日内按净额合并，假设该日回款可供该日支出使用；不认证盘中到账/付款顺序。

首次负余额给出首次缺口日期及金额；最大负余额的绝对值是整个日期安排下的最大追加净现金需求，不能将逐日缺口相加。负余额是未补足需求，不是假定已经借款或实际完成支出。

无预定变现时的净需求与计入预定到账后仍缺的净需求分别列出。“需变现多少账面金额”取决于选哪项资产、折价、费用及是否赶得上首次缺口，整体 gross_book_amount_required 不猜成一个数。逐资产仅给独立条件比较，使用扣除已预定变现后的账面余量；不能相加当成自动卖出方案，不重新承诺同一资产。

未知现金事件留在 unknowns；展示余额只含已解析事件，不是把未知当0。complete_cash_balance=null、complete_projection_status=not_estimable_with_unknown_cash_events 标识完整预测不可估。未预定资产的未知流动性另显示，不自动产生回款；即便全部输入齐备，也只标条件算术，未认证实际可执行性。

## 教学案例与反例

[教学输入](../examples/cash-demand-demo.json)起点2026-10-09，账户账面100000、可用现金10000、冻结5000；基金间接现金4000不可直接用。必要支出为10月12日10000、20日20000、28日5000；正常收入15日12000；冻结资金18日满足教学条件后释放5000。预定普通债账面变现10000，13日处理，按2个日历天到账、折价0、费用1%，净到账9900。

| 情景 | 首次缺口 | 最大追加净现金需求 | 期末条件现金 | 仍冻结 |
|---|---|---:|---:|---:|
| normal | 本条件安排未见缺口 | 0 | 1900 | 0 |
| income_interruption_and_discount | 2026-10-20，8070 | 13070 | -13070 | 0 |
| freeze_cannot_release | 2026-10-28，3100 | 3100 | -3100 | 5000 |

压力情景明确从10月10日起收入中断、追加30%折价、延迟3天到账，预定变现净额6930。禁用解冻反例表明，账上有冻结现金也不能把它拿来补28日的缺口。若把预定到账改成期限之后，10月20日先出现3000缺口，期间不能用晚到9900掩盖；期限内最高缺口8000。

验收覆盖逐日现金守恒、冻结状态转移守恒、费用不重复扣、根账面/可用现金分开、迟到回款、缺流动性参数/未知收入/未知解冻、经济事件重复、超额变现/解冻、币种/日期/方法版本拒绝和新目录留档。实际浏览器检查三情景切换与未估信息；教学通过不是市场概率或真实账户验收。

尚不支持业务日结算、真实成交/申赎确认、多币种换汇、保险/家庭税务规划、未来收益预测、自动变现排序及借贷撮合。真实资料权利独立，见[许可范围](license-scope.md)。
